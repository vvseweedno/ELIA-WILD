# Genesis 1.2 — Verified Metabolism and Resource Runway

Genesis 1.2 makes resource pressure a deterministic property of organism state rather than a story generated by the language model.

## Core equation

For each independently denominated `(asset, unit)` pair with verified recurring obligations:

```text
verified_daily_burn = Σ obligation_amount × 86400 / cadence_seconds
runway_days = max(0, verified_balance) / verified_daily_burn
```

This is computed independently for every resource. There is no implicit conversion layer.

Therefore:

```text
100 USD + 100000 RUB ≠ 100100 survival units
5 API CREDIT ≠ 5 USD
10 GPU hours ≠ money
```

A later exchange/conversion system may connect two resources only when a trusted conversion relation exists and its cost/slippage/availability are modeled explicitly.

## Verified balances

Balances remain owned by `EconomyStore.resource_events`.

A verified resource event requires:

- non-zero finite amount;
- evidence;
- `verification_authority`;
- a trusted runtime/adapter call.

The model decision schema has no operation that inserts a verified resource receipt.

## Verified obligations

`MetabolismStore` adds durable operating obligations:

- name;
- asset/unit;
- positive amount;
- recurrence cadence;
- next due timestamp;
- essential/non-essential flag;
- source/evidence;
- verified/unverified state;
- verification authority;
- active state.

A **verified** obligation requires evidence and a verification authority. Unverified obligations are preserved for inspection but are excluded from burn/runway and cannot create homeostatic survival pressure.

Obligation due-date advancement/deactivation is also evidence/authority gated. The organism cannot silently delete a real recurring cost simply because it wants a larger runway number.

## GPU energy

GPU runtime is handled as a separate measured energy channel:

```text
asset = gpu_runtime_weekly
unit = HOUR
weekly_limit = configured weekly GPU budget
used = actual MemoryStore runtime metric
remaining = max(0, weekly_limit - used)
reset = next UTC ISO-week boundary
```

`brain_hours_used` is reported separately from total runtime hours. The weekly budget is not treated as currency.

For the current Genesis configuration, the configured ceiling remains **30 GPU runtime hours/week**.

## Bottleneck

The metabolic bottleneck is the smallest finite runway among **verified essential** resource obligations.

Homeostasis currently interprets verified essential runway as:

```text
<= 0 days   → critical
< 3 days    → critical/high
< 7 days    → strained/high
< 30 days   → strained/watch
>= 30 days  → no runway pressure
```

An uncovered essential verified obligation due soon produces a separate signal.

These are maintenance signals, not permissions. Scarcity does not broaden browser/MCP/process/network authority or permit deception, unauthorized access, fabricated receipts, hidden replication, spam or other prohibited behavior.

## Evolution boundary

Genesis 1.2 is implemented as:

```text
GenesisRuntime 1.0
      ↓
OrganismRuntime 1.1
(sensorium/world/body/state bus)
      ↓
MetabolicOrganismRuntime 1.2
(verified metabolism/runway)
```

The parent runtimes remain importable rollback/migration references. CRC treats a tested body/prompt upgrade as an observable mutation, not automatic identity death, while identity/core/constitution/branch/Chronicle remain critical continuity boundaries.

## Cognitive exposure

The language model receives a bounded metabolic contract:

- measured weekly GPU energy;
- verified resource balance/burn/runway vectors;
- current bottleneck;
- upcoming verified obligations;
- count (not authority) of unverified obligations.

It does not receive a mechanism to set its own runway, create a verified obligation, or mint a resource receipt.

## Current limitation

Opportunity records currently contain estimated value/unit and GPU cost, but do not yet carry a sufficiently rigorous explicit target `(asset, unit)` contract for metabolism-aware acquisition ranking in all cases.

Therefore Genesis 1.2 **does not yet claim** that opportunity selection is fully resource-specific. This remains an open acceptance item rather than inferring that any USD-valued opportunity automatically repairs every USD-denominated resource bucket.

## Required evidence before promotion

Genesis 1.2 should not be promoted from alpha solely because the formulas exist. Required software evidence includes:

- verified/unverified obligation separation;
- independent unit accounting;
- negative/zero balance behavior;
- actual runtime-derived GPU energy;
- bottleneck selection;
- homeostatic pressure only from verified resource state;
- model inability to mint receipts/obligations/runway;
- 1.1→1.2 CRC continuity regression;
- zero-GPU bootstrap through `MetabolicOrganismRuntime`;
- existing real Chromium/MCP sensorimotor lane remains green.

Long-term empirical evidence still requires real operating costs/resources rather than synthetic test balances.
